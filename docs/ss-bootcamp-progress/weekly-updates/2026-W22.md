# 2026-W22 Progress

## Current Stage

Manalio is a PoC-stage prototype for childcare teacher training schools. The current focus is not adding many new features, but making the product easier to review, safer to explain, and ready for the next PoC discussion.

## What Changed This Week

- Public demo and GitHub supplement were prepared as the external-facing entry points.
- A limited educator review package was sent to two educators, using fictional sample cases and a feedback form.
- The review scope was clarified: student flow, educator-facing review points before interviews, school diary format fit, privacy-sensitive wording, storage scope, and possible PoC conditions.
- Public and private repositories were separated. This public repository is only a curated cutout; internal work logs and private review details stay outside it.
- Safety boundaries were tightened around export behavior, service-role API usage, and public sharing.
- The student flow wording was simplified around practicum-site feedback: students now see “advice summary,” “my understanding,” “what I am still unsure about,” and “what I want to observe or try tomorrow,” instead of wording that sounded like a report-writing task.
- The educator-facing wording was adjusted from abstract “issue organization” toward concrete support actions: what to discuss in an interview, what to bring into class, and what to return to the student.
- The student entry screen now shows a compact “next action” strip, so mobile users can see whether they should choose a fictional sample, write one observed scene, or proceed to the safety check.
- Fictional sample cards now show which sample is currently loaded. This reduces confusion during demos and educator review because the reviewer can tell whether they are looking at a provided fictional case or their own fictional input.
- The mobile student view was tightened again by hiding the redundant single-item navigation for students and compressing the signed-in header. This keeps the first useful action closer to the top of the screen on a phone.
- Public page copy now explains educator support as “points educators review before student interviews,” instead of vague “interview summary” wording.
- A first-PoC frame was drafted internally, separating educator-only re-review from a very small student PoC and clarifying scope, storage, success criteria, and stop conditions.
- Export behavior was kept conservative while educator feedback is pending. CSV/JSON log export remains off by default until the school-side storage and handling rules are agreed. If export is enabled later, the current design keeps only summary metadata such as date, age label, scene label, text length, and privacy-check flags, not raw student input text.
- Current explanatory docs were synced to use “educator review points before student interviews” instead of vague “interview summary” language, so the product reads as support for educator preparation rather than monitoring or grading.
- A safer educator-feedback intake flow was added. Incoming feedback is not copied verbatim into the repository or public notes; it is converted into role labels and structured into request, reason, impact, and next-check fields before being translated into PoC actions.

## What This Makes Possible

- SS members and mentors can open the public demo and understand the product direction without needing private access.
- Educator feedback can be collected separately and then translated into a smaller PoC scope.
- Weekly progress can be shared as product evidence instead of only as chat updates.
- Public progress can mention safety and wording improvements without exposing private review URLs, accounts, passwords, school names, or real practicum cases.
