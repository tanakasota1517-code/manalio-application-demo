# 2026-W22 Progress

## Current Stage

Manalio is a public prototype for childcare teacher training schools. The current focus is to make the core learning loop easy to understand: students write their own observations, review safety-sensitive wording, receive reflection prompts, and connect practicum-site feedback to the next day's observation.

## What Changed This Week

- Public demo and GitHub supplement were prepared as the external-facing entry points.
- A limited educator review package was sent to two educators, using fictional sample cases and a feedback form.
- Public and private repositories were separated. This public repository is only a curated cutout; internal work logs and private review details stay outside it.
- Safety boundaries were tightened around export behavior, service-role API usage, and public sharing.
- The student flow wording was simplified around practicum-site feedback: students now see "advice summary," "my understanding," "what I am still unsure about," and "what I want to observe or try tomorrow," instead of wording that sounded like a report-writing task.
- Fictional sample cards now show which sample is currently loaded. This reduces confusion during demos because reviewers can tell whether they are looking at a provided fictional case or their own fictional input.
- The mobile student view was tightened by hiding redundant navigation for students and compressing the signed-in header. This keeps the first useful action closer to the top of the screen on a phone.
- The educator-facing wording was adjusted toward concrete support actions: what to discuss with a student, what to bring into class, and what to return to the student.
- Export behavior was kept conservative while educator feedback is pending. CSV/JSON log export remains off by default until the school-side storage and handling rules are agreed.

## What This Makes Possible

- SS members and mentors can open the public demo and understand the product direction without private access.
- Educator feedback can be collected separately and translated into product decisions without copying raw private responses into public notes.
- Weekly progress can be shared as product evidence instead of only as chat updates.
- Public progress can mention safety and wording improvements without exposing private review URLs, accounts, passwords, school names, or real practicum cases.

## Next Focus

- Validate whether the public demo explains the value quickly enough.
- Keep the student first-use flow short enough that reviewers can understand the core experience without reading a long instruction page.
- Re-check the student mobile flow after any copy or layout change, because small header or navigation changes can push the actual input area too far down.
- Keep the educator screen focused on support and conversation preparation, not monitoring or grading.
- Keep public updates in sync with the demo repository without exposing private review URLs, accounts, passwords, or school-specific information.
- Regenerate the public candidate from the internal work repo and run local audits before each public repository update.
