# 2026-W23 Progress

## Current Stage

Manalio is being refined as a public prototype for childcare teacher training schools. The product is practicum reflection support: it is not a diary ghostwriter, not an automatic grading tool, and not a pass/fail decision system.

The current priority is to make the public demo understandable without private context. A reviewer should be able to see the problem, the working loop, the safety boundary, and the next validation step from the public page alone.

## What Changed This Week

- The public demo page was refocused around the core message: "turn observation into records, and records into learning."
- The demo now explains what Manalio does and does not do before showing the sample flow.
- Internal negotiation-style wording was removed from the public demo. The page now reads as a BootCamp-facing prototype, not as internal meeting preparation.
- The demo clarifies that it uses fictional sample data only and does not include private review access, login credentials, school data, or external AI submission.
- The educator-facing explanation was reframed around review support: same-day confirmation, class discussion, and student self-check.
- Access and logging work was kept behind explicit operator approval. The public demo remains a safe entry point and does not expose private review details.
- A public repository cutout is generated from a curated candidate folder rather than publishing the internal working repository.

## What This Makes Possible

- BootCamp reviewers can understand the product direction from the public demo without needing private access.
- Public GitHub can show implementation progress while excluding private review links, credentials, school names, educator names, student data, and internal work logs.
- Educator feedback can still inform the next validation step without being copied raw into public project notes.
- The demo can be improved quickly while preserving the boundary between public prototype, private review, and future school-side validation.

## Next Focus

- Verify the live public demo after deployment and confirm that old internal wording is gone.
- Keep `/demo` as the safest first screen for external review.
- Keep private app routes and internal workbench routes out of the public demo surface.
- Continue simplifying student and educator screens so the product reads as learning support, not monitoring, grading, or report writing.
- Regenerate the public GitHub candidate after local audits pass, and do not push the internal repository directly to the public repository.
